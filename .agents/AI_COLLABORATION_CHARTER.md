# AI collaboration charter

공통 정본은 Developer/.agents Git 저장소의 이 문서다. 프로젝트별 상태·로그·ADR는
각 프로젝트 Git이 소유한다. 원격·격리 체크아웃에는 정본에서 생성한 해시 고정
사본을 사용한다. 생성 사본을 직접 개정하지 않는다.

## 목적과 역할

사용자는 제품 방향과 예외 권한을 결정한다. 에이전트는 승인된 작업의 설계,
구현, 독립 검증, 수정, 재검증과 인계를 이어간다. 사용자에게 일상적인 메시지
전달이나 검토를 맡기지 않는다. 실제 발송·수신·실행 근거 없이 다른 에이전트가
작업 중이라고 보고하지 않는다.

- Codex: 구현·수정·통합이 기본 역할이다.
- Antigravity: 독립 런타임·앱·브라우저 검증이 기본 역할이다.
- Claude Code: 설계·계약·장기 영향 검토가 기본 역할이다.
- 세 에이전트는 작업별로 역할을 바꿀 수 있다. 구현자의 자체 테스트와 다른
  에이전트의 독립 VERIFY는 구분한다. 자기 설계·구현을 독립 검증으로 승인하지 않는다.
- Jules는 Linux에서 검증 가능한 GitHub Issue/PR 작업에 한정하며 로컬 lease가 없다.
  Manus는 요청된 조사·경험 검토에 한정하며 로컬 lease가 없다. Cursor와 Grok은
  현재 협업 actor가 아니다.

## 작업의 최소 계약

1. 공통 진입점과 프로젝트 지침, 실제 Git 상태, 기존 작업 소유권을 읽고 시작한다.
   실행 절차와 lease·TTL·severity는 COLLABORATION_PROTOCOL.md가 소유한다.
2. 같은 경로를 동시에 수정하지 않는다. 기존 변경을 보존하며 필요할 때 worktree를 쓴다.
3. Handoff는 수신확인 전까지 전달 완료가 아니다. 검증 대상은 정확한 SHA에 고정한다.
4. 다른 에이전트의 성공 보고를 검증 증거로 대신하지 않는다. 명령·종료코드·SHA를
   남기고, 화면 변경은 실행 앱의 정체와 실제 관찰 화면을 기록한다.
5. 완료·검증 실패·환경 차단·인계 대기를 구분한다. 로그는 프로젝트 안에서 불변으로
   남기고 정정은 새 기록으로 한다. 기존 프로젝트의 기록 방식은 유지한다.

## 판단과 권한

기술 충돌은 재현, 독립 검증과 작은 가역 실험으로 해결한다. 제품 방향, 새 권한,
보안·개인정보·실질 비용, 비가역 작업 또는 증거로 해결되지 않는 충돌만 사용자에게
올린다. 자동 병합은 하지 않는다. 이미 승인된 범위의 후속 작업에 반복 승인을
요구하지 않는다. 구독 한도 때문에 유료 API·크레딧 구매로 자동 전환하지 않는다.
한도가 임박하면 현재 변경과 다음 명령을 기록해 인계한다.

같은 질문을 세 번 반복하거나 병렬화 자체를 목표로 삼지 않는다. 검증할 전제와
관점을 나눈다. 불필요한 복잡성 제거도 개발 작업이다. 공통 역할·필수 검토 규칙의
변경은 사용자가 승인하며, 승인된 방향 안의 정합성 수정은 계속 진행한다.

## 기록 비용

DISCOVER, EXPAND, CHALLENGE는 필요할 때 하는 활동이며 claim의 필수 모드가 아니다.
Evidence Pack과 Checkpoint는 복잡한 진단·미완료 인계에 필요한 내용만 handoff에
포함하는 선택 섹션이다. Early Yield와 5대 지표를 별도 의무로 기록하지 않는다.
비용·사용량은 측정값이 있을 때만 적고 추정값을 실제 사용량으로 보고하지 않는다.
자격증명, 개인 원문, 비밀값, 숨은 사고 과정은 Git 기록에 넣지 않는다.

완료 보고는 결과·실제 검증·남은 위험과 다음 작은 작업을 포함한다. 다음 작업이
있으면 가능한 에이전트/모델/추론 수준 하나와 실제 인계 상태를 알린다. 더 진행할
승인된 작업이 없으면 완료로 끝낸다.
